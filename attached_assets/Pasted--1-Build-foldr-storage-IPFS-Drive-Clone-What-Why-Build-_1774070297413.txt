#1 - Build foldr.storage — IPFS Drive Clone
What & Why
Build a full-stack Google Drive/Dropbox clone called "foldr.storage" using Lighthouse.storage (IPFS + Filecoin) as the primary backend. Polished Drive-like UI with drag-and-drop uploads, full Kavach encryption (share, revoke, token-gate, decrypt), and a Pinata fallback. Annual plan — real deletion from Lighthouse is supported.

Done looks like
Polished React web app at / — Drive-like layout (sidebar, grid/list, top bar)
Register/login with email+password (bcrypt + JWT in httpOnly cookie)
Upload via button or drag-and-drop; per-file progress bars; encrypt toggle
File grid shows name, size, type icon, date, storage badge (Lighthouse/Fallback), lock icon for encrypted
Plain download: redirect to Lighthouse IPFS gateway
Encrypted download: server fetches decryption key via Kavach, streams decrypted file back
Share encrypted file with another wallet address (grants decryption shard access)
Revoke access from a wallet address
Token-gated access: set NFT/token ownership condition on an encrypted file
Delete: soft-delete in DB + lighthouse.deleteFile by UUID (Annual plan = real deletion)
Public share links at /share/:token — no login required
GET /api/status → { backend: "lighthouse" | "fallback" }
Auto-fallback to Pinata if LIGHTHOUSE_API_KEY missing or initialization fails
Out of scope
Filecoin deal management
Admin panel, multi-tenant
Mobile app
Browser Passkey/MetaMask auth in this iteration (server uses signed message + JWT; frontend wallet connect is a future enhancement)

Kavach import
import kavach from "@lighthouse-web3/kavach"  // default import
import lighthouse from "@lighthouse-web3/sdk"
import { ethers } from "ethers"
Server-side auth helper (used for ALL encryption operations)
// Generates a JWT from ETH_PRIVATE_KEY — reuse per request or cache per session
const getKavachJWT = async (privateKey: string): Promise<string> => {
  const signer = new ethers.Wallet(privateKey)
  const authMessage = await kavach.getAuthMessage(signer.address)
  const signedMessage = await signer.signMessage(authMessage.message)
  const { JWT } = await kavach.getJWT(signer.address, signedMessage)
  return JWT
}
// signer.address is the server's wallet public key — store as WALLET_ADDRESS derived from ETH_PRIVATE_KEY
Plain upload — lighthouse.uploadBuffer (buffer, no temp file needed)
const response = await lighthouse.uploadBuffer(buffer, apiKey)
// response.data.Hash = CID
// response.data.Name = filename
// response.data.Size = size string
Encrypted upload — lighthouse.uploadEncrypted (REQUIRES TEMP FILE PATH, not Buffer)
// IMPORTANT: uploadEncrypted only accepts a file path string, not a Buffer.
// Multer stays in memoryStorage. Write buffer to a temp file, pass path to Lighthouse, then delete.
import fs from "fs/promises"
import os from "os"
import path from "path"
import crypto from "crypto"
// Inside the upload route handler, after multer populates req.file:
const tmpDir = os.tmpdir()
const tempName = crypto.randomBytes(16).toString("hex") + "-" + file.originalname
const tempPath = path.join(tmpDir, tempName)
try {
  await fs.writeFile(tempPath, file.buffer)
  const jwt = await getKavachJWT(process.env.ETH_PRIVATE_KEY)
  const walletAddress = new ethers.Wallet(process.env.ETH_PRIVATE_KEY).address
  const response = await lighthouse.uploadEncrypted(tempPath, apiKey, walletAddress, jwt)
  // response.data[0].Hash = encrypted CID
  // response.data[0].Name, response.data[0].Size
} finally {
  await fs.unlink(tempPath).catch(() => {})  // best-effort cleanup, never throws
}

Token-gated access — set condition
const jwt = await getKavachJWT(process.env.ETH_PRIVATE_KEY)
const walletAddress = new ethers.Wallet(process.env.ETH_PRIVATE_KEY).address
const conditions = [{
  id: 1,
  chain: "Optimism",            // e.g. "Ethereum", "Polygon", "Optimism"
  method: "balanceOf",          // contract method
  standardContractType: "ERC721",
  contractAddress: "0x...",
  returnValueTest: { comparator: ">=", value: "1" },
  parameters: [":userAddress"]
}]
const aggregator = "([1])"      // logical grouping of condition ids
await lighthouse.applyAccessCondition(walletAddress, cid, jwt, conditions, aggregator)
// Response: { data: { cid, status: 'Success' } }
Decrypt encrypted file (server-side)
const jwt = await getKavachJWT(process.env.ETH_PRIVATE_KEY)
const walletAddress = new ethers.Wallet(process.env.ETH_PRIVATE_KEY).address
// Step 1: Get the raw decryption key from Kavach (server-safe, no browser APIs)
const keyObject = await lighthouse.fetchEncryptionKey(cid, walletAddress, jwt)
// keyObject.data.key = hex string of the raw symmetric key
// Step 2: Fetch the encrypted file bytes from the IPFS gateway
const encryptedResponse = await fetch(`https://gateway.lighthouse.storage/ipfs/${cid}`)
const encryptedBuffer = Buffer.from(await encryptedResponse.arrayBuffer())
// Step 3: Decrypt using Node.js crypto directly — bypasses lighthouse.decryptFile
// which may rely on browser-only Blob/DOM APIs.
// At build time: inspect node_modules/@lighthouse-web3/kavach to confirm the
// exact algorithm (expected: AES-256-GCM), key length, and IV/tag layout,
// then implement crypto.createDecipheriv accordingly.
// If the SDK exports a Node-compatible decrypt helper, prefer that over manual crypto.
// Fallback shape (AES-256-GCM assumed):
import crypto from "crypto"
const key = Buffer.from(keyObject.data.key, "hex")
const iv = encryptedBuffer.slice(0, 12)
const authTag = encryptedBuffer.slice(12, 28)
const ciphertext = encryptedBuffer.slice(28)
const decipher = crypto.createDecipheriv("aes-256-gcm", key, iv)
decipher.setAuthTag(authTag)
const decrypted = Buffer.concat([decipher.update(ciphertext), decipher.final()])
// Stream decrypted back to client with correct Content-Type header
Build-time action: Before writing the decrypt route, inspect node_modules/@lighthouse-web3/kavach/dist/ TypeScript types and README to confirm: (1) exact algorithm, key/IV/tag byte layout, (2) whether the SDK exports a Node-compatible decrypt utility. Use the SDK helper if it exists; fall back to the manual crypto.createDecipheriv approach above if not.
